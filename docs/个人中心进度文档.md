## 1. 产品定位与闭环（2026-08-21 讨论确定）

本项目是面向**计算机及相关专业学生的求职智能体**。产品由三个模块构成，个人中心是其中唯一的事实底座：

| 模块 | 职责 | 与个人中心的关系 |
| --- | --- | --- |
| 简历工作区 | 编辑简历；与 Agent 聊岗位侧重，获取修改建议 | 从个人中心拉取**已确认事实**生成内容，字段级 diff 确认后写入，AI 不静默覆盖正文 |
| 面试题生成 / 模拟面试 | 基于简历生成八股文、项目深挖、软素质三类题；模拟面试对练 | 只读取简历导出时的**版本快照**，保证练的题与面试官看到的简历一致 |
| **个人中心（本部分）** | 用户的可信求职信息仓库 | 一切生成物的来源；接收面试反馈回流，越用越厚 |

### 1.1 核心叙事

学生在个人中心养一个"可信的自己"：JD 告诉他缺什么，简历和面试题都从这个仓库长出来，每次面试的挫败又反过来把仓库养厚。

### 1.2 闭环六阶段

1. **建设信息仓库**：填固定信息、导入项目、Agent 访谈补全成事实卡。Agent 只提问、不编造。
2. **瞄准岗位（JD 驱动）**：粘贴 JD，Agent 对比信息库找差距，转成"待补充问题"队列，按优先级补齐。
3. **生成简历**：从确认事实生成项目描述；聊天式修改建议；字段级 diff 勾选后应用。
4. **导出与投递**：导出时保存版本快照；记录投递公司与进度。后续面试练习绑定快照。
5. **面试准备**：基于快照生成八股/项目深挖/软素质题；模拟面试对练。
6. **反馈回流（回到阶段 1）**：被问倒的八股进错题本；说不清的项目细节变成新的待补充事实回到访谈队列；真实面试题沉淀入库。

### 1.3 个人中心内部结构（三区域）

```text
个人中心 · 可信信息仓库
├── 固定信息：基本资料、教育背景（多段）、求职目标与状态、技能标签
├── 项目经历：事实卡与确认状态、证据原文定位、完成度评分、简历版/面试版两套输出
└── 沉淀与反馈（新增）：待补充问题队列、八股错题本、真实面试题、投递进度
```

关键设计原则：

- **只读消费**：简历、面试题、模拟面试只读取 `confirmed` 状态的事实，不反向静默写仓库。
- **两层深度输出**：每个项目经历产出两套描述——"简历一句话版"（STAR 结构，缺结果不写结果）和"面试深挖版"（决策、权衡与可被追问的细节），外加写法建议。
- **完成度驱动，而非填表驱动**：不要求用户"填完"信息库；冷启动只需姓名、教育、一个项目。缺什么由 JD 对比和面试追问暴露，转成待补充问题队列驱动补齐。
- **项目产出四件套**：项目梗概、技术栈、本人负责链路、简历写法建议——均由访谈 Agent 产出候选、用户确认后生效。

> 注意：第 1.2 节的阶段 2/4/6 与第 1.3 节"沉淀与反馈"区域为本次讨论新增的设计，**尚未写入实施方案 V1.0**；开发到对应功能时应同步修订 `docs/个人中心信息库实施方案.md`。

## 4. 与设计目标的当前差距

以下为第 1 周迭代尚未补齐、或与方案设计存在简化偏差的点，后续开发时需要处理：

| 差距 | 设计要求 | 当前现状 |
| --- | --- | --- |
| 乐观锁 | `profiles.version` 字段，`PATCH` 请求携带 `version` 防止并发覆盖 | 未实现 |
| 多段教育经历 | 独立 `educations` 表（学校/学历/专业/起止时间/在读状态可多段） | 单值字段直接放在 `profiles` 表（`school`、`major`、`graduation_date`、`study_status`），仅支持一段 |
| 求职目标 | 独立 `career_targets`（目标城市、期望薪资、待解决问题），薪资加密 | 仅有 `target_role`、`job_status` 在 `profiles` 表，无薪资字段 |
| 技能标签 | `skill_tags` 表，可增删标签 + 熟悉度 | 未实现 |
| 敏感字段加密 | 手机、邮箱、期望薪资加密存储（`*_ciphertext`） | 明文存储 |
| 手工项目 CRUD | `projects` 表 + `GET/POST /projects`、`GET/PATCH/DELETE /projects/{id}` | 未实现 |
| 表单分块保存 | 按块独立保存并显示"已保存于 xx:xx" | 当前为整表单一次提交 |
| 保存状态语义 | 失败时明确"保存失败，可重试"，不伪装已保存 | 已有基础错误提示，符合最低要求 |
