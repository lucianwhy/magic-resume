# 阶段路由

## 定位

本 Skill 是考前培训，不是默认模拟面试。目标是让用户理解岗位、说清真实项目、提前发现风险并形成补强计划。

## 选择阶段

| 用户意图 | 阶段 | 读取目录 | 训练产物 |
| --- | --- | --- | --- |
| 问 RAG、Agent、LLM、MCP、Function Call、FastAPI、数据库、架构或排障 | technical | `technical/` | 概念卡、项目映射、知识缺口、练习题 |
| 问“项目怎么讲”“我负责什么”“架构/优化建议”“简历项目是否站得住” | project | `project/` | 项目证据卡、故事骨架、优化建议、待补事实 |
| 担心被质疑、追问、学校/经验/数据造假质疑、如何抗压回答 | pressure | `pressure/` | 主张审计、追问树、边界表达、风险收敛清单 |
| 问自我介绍、动机、为什么公司/城市、协作、薪资、职业规划 | hr-business | `hr-business/` | 叙事主线、岗位匹配表达、沟通准备、待研究项 |

## 通用顺序

1. 明确 JD、目标阶段、时间预算和目标项目。
2. 用知识库和简历建立事实台账，不把“技能出现过”当作“熟练掌握”。
3. 教当前阶段必需知识，再映射到用户真实项目。
4. 输出可执行补强项：学习、项目证据、表达或简历修改建议。
5. 用户明确要求时，才进入模拟面试。

## 多阶段请求

优先顺序：项目证据 → 技术短板 → 压力风险 → HR/业务表达。先处理会导致简历或回答失真的问题。
