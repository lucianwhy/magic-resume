# 项目面考前培训

## 训练目标

把项目从“功能罗列”变成可验证工程故事。培训应帮助用户解释自己参与什么、具体负责什么、怎么设计、为什么这样取舍、如何验证，以及下一步如何优化。

## 项目证据卡

每个项目先补齐下表。未知就写未知，不能用推测填满。

| 字段 | 应回答内容 |
| --- | --- |
| 业务问题 | 谁在什么场景遇到什么低效/风险。 |
| 成功标准 | 用户、业务或技术上如何判断有效。 |
| 我的边界 | 独立负责的页面、接口、模型链路、部署或协调事项。 |
| 架构与数据流 | 输入从哪里来，经过哪些服务/Agent/数据库，输出给谁。 |
| 关键决策 | 至少一个选择及替代方案，例如混合检索而非纯向量。 |
| 难点与处理 | 真正遇到的问题、定位方法、解决或降级。 |
| 结果与证据 | 交付链接、代码、截图、用户数、时间、验收方式及口径。 |
| 边界与下一步 | 没做什么、风险是什么、会怎样迭代。 |

## 四段工程叙事

1. **场景与目标**：一句话说用户和问题，避免从技术名开场。
2. **本人贡献**：明确“我负责”，而不是泛称“我们做了”。
3. **技术方案**：用输入 → 处理 → 存储/工具 → 输出描述数据流。
4. **验证与反思**：说结果口径、真实不足和下一步。

示例骨架：

> 面向 `<用户>` 的 `<问题>`，我负责 `<明确模块>`。输入是 `<数据>`，经过 `<关键逻辑/系统>`，输出 `<价值>`。选择 `<方案>` 是因为 `<取舍>`。通过 `<证据>` 验证；目前 `<边界>`，下一步会 `<改进>`。

## 优化建议生成规则

先分为“已做事实”和“建议方案”。建议必须说明解决什么问题、代价和验证方法。

| 项目类型 | 常见可讨论优化 | 验证方式 |
| --- | --- | --- |
| RAG 应用 | 元数据过滤、混合检索、重排、引用校验、拒答、离线评估集 | 命中率、引用正确率、人工评测、延迟/成本 |
| Agent 系统 | 合并无独立职责节点、状态 schema、失败重试/降级、工具权限、链路日志 | 成功率、失败定位时间、成本、人工介入率 |
| FastAPI 后端 | 分层、参数校验、异步 I/O、连接池、缓存、限流、健康检查 | P95 延迟、错误率、吞吐、压测 |
| 数据库 | 索引、分页、批量读写、避免 N+1、缓存 | 执行计划、扫描行数、查询耗时 |
| 小程序/产品 | 埋点、漏斗、反馈入口、灰度、隐私说明 | 激活、留存、任务完成率、反馈 |

## 常见风险修复

- “独立开发”：准备需求、设计、代码、部署各自的证据，说明外部依赖。
- “300+ 用户”：准备统计定义、截止日期、后台截图；不知道留存就说未统计。
- “7 Agent”：准备每个 Agent 的职责、输入输出和不存在时的替代方案。
- “上线”：说明域名、部署、服务依赖、监控/日志；不要把“本地能跑”说成上线。
- 项目名称不清：先统一正式名称、时间、团队和用户对象。

项目培训默认产出“项目证据卡 + 90 秒叙事 + 优化建议 + 待补事实”，不进行当场模拟。
