# 培训设计

把每轮面试准备设计成“诊断 → 微课程 → 练习 → 验收 → 补缺”，不是知识堆砌，也不是默认模拟面试。

## 1. 能力等级

对每个主题分别判断当前等级和 JD 所需目标等级。证据不足时写“待评估”，不要凭简历关键词推断掌握程度。

| 等级 | 可观察表现 |
| --- | --- |
| L0 未知 | 未接触，或无法辨认概念。 |
| L1 识别 | 能给出基本定义，知道它解决什么问题。 |
| L2 解释 | 能讲清最小架构、核心流程和主要组件。 |
| L3 应用 | 能映射到自己的真实项目，说明本人动作和结果。 |
| L4 取舍 | 能解释方案选择、失败模式、排障和边界。 |
| L5 优化 | 能提出可验证的优化方案，并说明评估指标和代价。 |

不要用单一总分掩盖差异。同一主题可以“理解 L4、项目证据 L2、表达 L3”。

## 2. 缺口分类与优先级

每个主题检查四类缺口：

- `knowledge`：概念、架构、原理不知道。
- `application`：知道概念，但不会用于场景、设计或排障。
- `expression`：会做，但不能用面试语言讲清楚。
- `evidence`：缺少本人职责、产物、数据或可核验材料。

优先级按“岗位重要度 × 缺口大小 × 面试紧迫度”判断。先处理硬性要求和高风险简历主张，不从最容易的话题开始。

## 3. 微课程模板

一次只解决一个清晰目标，建议 5–15 分钟：

1. `为什么会考`：它对应哪条 JD 或哪项简历主张。
2. `一句话定义`：用户能复述的最小准确解释。
3. `最小架构`：输入、关键步骤、输出及失败点。
4. `项目映射`：只连接到已确认的个人事实。
5. `常见误区`：最可能说错或说过头的地方。
6. `表达边界`：可以说、需要限定、不能声称什么。
7. `五分钟练习`：解释、画流程、比较方案或排障一题。
8. `通过标准`：本轮结束时必须出现的可观察表现。

用户已经达到目标等级时跳过教材，改做查漏或更高阶取舍；用户没有项目证据时，不把练习答案写成个人经历。

## 4. 训练评估

每个主题至少检查四项：

| 维度 | 通过信号 |
| --- | --- |
| 理解 | 定义准确，能讲最小流程。 |
| 表达 | 能用精简版或展开版结构化说明，不依赖术语堆砌。 |
| 映射 | 能指出自己项目中的对应模块、动作和证据。 |
| 取舍 | 能说明至少一个限制、失败模式或替代方案。 |

评估结果写为：`通过`、`部分通过`、`待训练`、`缺证据`。必须说明依据和下一步，不能只给分数。

只评估用户明确标记为面试答案、项目介绍或自我介绍的文字。不要用聊天回复耗时、字数、口头语或日常交流方式推断表达状态、性格或情绪。

## 5. 阶段收口

阶段结束输出：已达标主题、仍有风险的主张、下一轮最高优先级、可回写知识库的事实候选。未经用户确认，不把训练中生成的示例写成事实。
