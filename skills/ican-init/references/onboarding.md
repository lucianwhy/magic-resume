# 初始化对话

## 原则

- 能从当前目录、文件和上下文确定的信息直接使用，不向用户确认。
- 能安全采用默认值的操作直接执行，执行后告知。
- 每次最多提出一个会改变后续路径的问题。
- 用户可以跳过目标岗位；将其记录为待补，不阻止初始化。

## 执行顺序

1. 检测当前目录及上级目录是否存在 `.ican/project.json`。
2. 已存在：运行 doctor，缺失项自动修复，随后继续当前任务。
3. 不存在：立即运行初始化脚本，不先询问目录和 Git 设置。
4. 初始化后检查当前对话或目录中是否已有简历、项目材料或职业知识库。
5. 无法判断时，只问：“你要导入已有简历/资料，还是从零开始建立？”

## 两条入口

### 导入已有资料

1. 提示用户提供简历文件、Magic Resume 简历 ID、项目材料或已有知识库路径。
2. 文件已经在当前上下文或工作区时直接读取，不重复索要。
3. 将原件保存在 `knowledge/sources/` 或对应业务目录；不得覆盖源文件。
4. 调用 `$ican-career-knowledge-base` 提取原子事实、来源和待核实项。
5. 再询问目标岗位或简历方向；当前对话已经给出时不得重复询问。

### 从零建立

1. 调用 `$ican-career-knowledge-base` 分步采集，不一次发送长问卷。
2. 首轮优先采集：姓名或称呼、教育/当前身份、一个最能代表用户的经历。
3. 每轮只问一个信息增益最高的问题。
4. 能形成基础事实后，再引导目标岗位或简历方向。

## 禁止

- 不询问“要在哪里创建目录”。
- 不询问“资料是否进入 Git”。
- 不要求用户先理解目录结构。
- 不因缺少简历而停止；转入分步创建流程。
